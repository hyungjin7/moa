# MOA 문서 이동·삭제·복원

관리자는 글 상단의 **이동 / 삭제 / 휴지통**을 사용한다. 기존 색상과 로그인 방식은 유지하며 일반 회원·공유 링크에는 관리 기능을 제공하지 않는다.

## 사용 방법

1. 글을 열고 **이동**을 누른다. 같은 프로젝트에서는 대상 그룹을 선택하거나 새 그룹 이름을 입력한다. 다른 프로젝트를 선택하면 원문·파일명·기존 그룹·이전 버전을 함께 옮긴다.
2. **삭제 → 휴지통으로 이동**을 누르면 일반 목록·검색에서 빠진다. 파일은 영구 삭제하지 않는다.
3. 글 상단 또는 프로젝트 홈의 **휴지통 → 복원**을 누르면 원래 프로젝트·그룹으로 돌아온다. 마지막 글을 삭제해 프로젝트가 목록에서 사라져도 홈의 휴지통에서 복원할 수 있다.
4. 대상 위치에 같은 이름의 글 또는 이전 버전이 남아 있으면 덮어쓰지 않고 중단한다. 프로젝트 이동 후 기존 주소·핀은 따라가지 않는다. 새 주소를 사용하고 필요한 경우 다시 고정한다.

프로젝트를 옮기면 대상 프로젝트 회원에게 글이 보인다. 기존 공유 링크는 이동·삭제 시 해제하며 복원해도 되살리지 않는다. 다시 공유하려면 새 링크를 만든다. 기존 공유 미디어 쿠키의 잔여 유효기간은 기존 제품 정책(최대 6시간)을 따른다.

## 기술 검토 결론

- `/api/doc/manage`는 middleware와 handler에서 관리자·계정 상태를 확인한다. 쓰기는 Origin·JSON·요청 크기를 검사한다. GET은 휴지통 메타데이터만 반환한다.
- 저장·이동·삭제·복원은 같은 프로세스 전역 문서 잠금을 사용하고 SHA-256 원본 버전을 비교한다. 현재 1 Pod/1 Node 프로세스가 전제다. 복제본을 늘리기 전 분산 잠금이 필요하다.
- 대상 파일을 독점 생성하고 기존 파일을 덮어쓰지 않는다. 원본 삭제 전 새 파일이 디스크에 기록된다. 원본 파일 삭제 실패 시 대상 파일과 버전 이력 위치를 되돌린다.
- 경로 탈출·문서 symlink/hardlink·허용 루트 밖 프로젝트·데모 문서 이동은 거절한다. 다른 프로젝트에서 상대 import가 깨지면 이동하지 않는다. 문서가 참조하는 공용 미디어는 자동 이동하지 않으므로 원래 미디어 경로를 유지한다.
- 휴지통은 `/data/.document-trash/<UUID>/`에 원문·원래 프로젝트/문서·작성자·삭제 시각·SHA-256·이전 버전을 보관한다. public 아래에 두지 않는다. 폴더 0700, 보관 파일 0600이며 Git·Docker 빌드에서 제외한다.
- `.document-trash`와 `.document-history`는 같은 NFS PVC에 보존된다. 외부 백업에는 두 폴더와 원문을 함께 포함한다. 이번 기능은 외부 백업이나 디스크 포렌식 삭제 기능이 아니다.
- 디스크 오류나 프로세스 강제 종료처럼 파일 시스템 사이의 완전한 트랜잭션이 불가능한 상황에서는 원문·휴지통·이전 버전의 존재를 먼저 확인한다. 오류 후 수동으로 보관 폴더를 비우지 않는다. 영구 삭제/휴지통 비우기 API는 제공하지 않는다.

## 검증·배포

격리 파일 시스템에서 권한·Origin·충돌·버전 이력 이동·휴지통·복원·경로 보호·오류 복구를 검사한다. 격리 브라우저에서 그룹/프로젝트 이동과 삭제/복원, 모바일 폭을 실제로 확인한다. 운영 배포는 기존 app/initContainer 이미지만 바꾸며 Secret·사용자·PVC는 유지한다. Recreate 배포 중 짧은 접속 중단이 있을 수 있다.

이전 이미지로 되돌려도 휴지통·이전 버전은 PVC에 남는다. 옛 버전에는 휴지통 UI가 없으므로 해당 저장 폴더를 지우지 말고 새 버전을 복구한 뒤 복원한다.

## 의존성 보안 패치

운영 빌드에서 발견된 기존 경고를 해결하기 위해 Next.js를 15.5.29로, 하위 PostCSS를 8.5.32로 패치하고 lockfile을 갱신했다. Next.js 16으로의 주 버전 변경은 하지 않았다. 최종 로컬 및 운영 이미지 빌드의 npm 감사 경고는 0개다. [Next.js 공식 보안 공지](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw)를 확인했다.

검증: 문서 편집·관리·LLM 27개, OIDC 14개 통과. 격리 브라우저에서 그룹 이동·프로젝트 이동·삭제·홈 휴지통 복원 및 390px 화면 가로 넘침 없음을 확인했다. 배포 전 실제 문서·버전 파일 43개를 백업하고 별도 디렉터리 복원 후 SHA-256을 모두 대조했다. 백업은 alpha의 `/home/hyungjin/.local/state/moa/document-management-20261112/`에 있으며 계정·Secret 파일은 포함하지 않았다.
