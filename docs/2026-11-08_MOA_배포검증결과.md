## Keycloak 클라이언트 등록 및 실제 인증 확인

사용자가 관리자 로그인과 최종 클라이언트 생성을 승인한 뒤, Keycloak 관리자 UI에서 `delvrio-internal` Realm에 `moa-web`을 등록했다. client authentication/standard flow/PKCE S256은 켜고 direct grants/implicit/service accounts는 껐다. 콜백과 로그아웃 URI는 MOA의 정확한 HTTPS 경로로 제한했다.

생성된 Client Secret은 서버 내부에서만 `moa/moa-auth`에 동기화하고 Deployment를 재시작했다. 값은 로그·화면·Mac·Git으로 내보내지 않았다. 실행 파드에서 실제 Keycloak 토큰 엔드포인트가 클라이언트 인증을 받아들이고 존재하지 않는 인가 코드는 invalid_grant로 거절하는 것을 확인했다(검수용 토큰 발급 없음).

실제 브라우저에서 MOA의 Keycloak 버튼 → 사용자 인증 → MOA 콜백 → “Keycloak 인증 완료: MOA 관리자에게 계정 연결 승인을 요청하세요.”까지 확인했다. Client not found 오류는 해결됐다.

현재 최초 사용자 승인 대기 1건, identity binding 0건, MOA team account 0건이다. Owner는 팀 계정이 아니므로, Owner로 로그인하여 팀 계정을 초대·생성하고 해당 Keycloak 사용자와 명시적으로 연결 승인해야 실제 MOA SSO 세션을 발급받을 수 있다. 이 최초 사용자 권한 부여를 자동으로 수행하지 않았다. 승인 후 프로젝트 열람·연결된 SSO 로그아웃의 실제 사용자 검수는 아직 남아 있다.

Owner 초기 비밀번호의 Mac 복사는 자동 승인 심사에서 거절되어 수행하지 않았다. 대신 비밀을 내보내지 않는 `scripts/set-k3s-owner-password.py`를 제공했다. 사용자가 직접 선택한 비밀번호의 해시만 SSH stdin으로 전송한다.

GitHub checks는 `npm ci`, 내부 LLM 테스트, OIDC 보안 테스트, 프로덕션 빌드를 수행한다. Git push 기반 K3s 자동 배포는 구성하지 않았으며 이번 배포는 검증된 digest로 직접 적용했다.

## 최초 관리자 설정 후속 확인

사용자가 자체 Owner 비밀번호 설정을 완료했다. 초기 무작위 비밀번호와 다르게 변경됐고, 실행 Pod의 비밀번호 해시가 현재 moa-auth와 일치함을 값 출력 없이 확인했다. Mac 기본 Python의 scrypt 미지원 문제는 Node crypto로 해시를 생성하도록 수정하고 합성 값으로 검사했다.
