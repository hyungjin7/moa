# MOA Markdown 문서 편집·미리보기·버전 복원

## 설계 결론

관리자가 기존 문서 상단의 **편집** 버튼에서 Markdown/MDX 원문을 수정하고, 기존 문서와 같은 렌더러로 저장 전 미리보기를 확인한다. 저장 전 문법 검증을 통과하면 파일을 원자적으로 교체하고 이전 내용과 새 내용을 버전으로 보관한다. 복원도 새 저장 작업으로 기록해 복원 직전 내용으로 다시 돌아갈 수 있다.

| 기능 | 동작 |
| --- | --- |
| 본문 편집 | Markdown·기존 MDX 컴포넌트와 상대 경로 import 지원 |
| 미리보기 | 편집·나란히 보기·미리보기 모드. 500ms 입력 대기 후 컴파일 |
| 저장 | 버튼 또는 Cmd/Ctrl+S. 문법 오류는 422, 충돌은 409로 원본 보호 |
| 이전 버전 | 저장 시각(KST)·작성자·변경 종류·원문 확인 |
| 복원 | 확인 창을 거쳐 적용. 복원 전 내용도 보관 |
| 미저장 보호 | 닫기 확인 및 브라우저 이탈 경고 |
| 권한 | 기존 관리자/Owner만 허용. 회원과 공유 링크는 편집 API 사용 불가 |

기존 인증 구조와 색상을 유지한다. 일반 회원에게 편집 권한을 새로 부여하지 않는다. 기존 MDX는 브라우저에서 JavaScript를 실행할 수 있는 신뢰된 관리자 문서 형식이므로 본문 작성 권한을 관리자에게 한정한다. 이 기능은 비신뢰 사용자용 MDX 샌드박스가 아니다.

## 기술 검토 결론

- 새 `/api/doc/source`, `/preview`, `/history`, `/restore` API는 middleware와 Node handler에서 모두 관리자 권한을 확인한다. 변경 요청은 Origin과 JSON 형식, 스트리밍 본문 크기를 검사한다.
- 파일당 UTF-8 512KiB, 문서당 최근 50개 버전을 보관한다. 첫 웹 저장 시 기존 문서도 보관한다. 변경 없는 저장은 버전을 추가하지 않는다.
- 버전은 `MOA_CONTENT_ROOT/.document-history/<문서 해시>/`에 원문·index로 저장한다. 운영에서는 `/data/.document-history`이며 기존 NFS PVC에 영구 저장된다. 디렉터리 0700·파일 0600, UUID 버전 ID와 SHA-256 무결성 검사를 적용한다. 버전은 웹에서 직접 다운로드할 수 있는 public 폴더에 두지 않는다.
- 원본 SHA-256을 비교해 다른 브라우저·에이전트·제목/그룹 변경과의 덮어쓰기를 차단한다. 소스·복원·메타데이터 API의 잠금은 Node global symbol로 공유한다. 현재 단일 Pod/단일 서버 프로세스 운영이 전제이며 다중 프로세스·다중 복제본 운영은 별도 분산 잠금이 필요하다.
- 기존 Markdown 표와 MDX 컴포넌트·상대 import를 같은 번들러로 렌더링한다. 미리보기는 원본 파일·문서 번들 캐시·버전 이력을 변경하지 않는다.
- 데모 문서, 허용 폴더 밖, 문서 파일 symlink/hardlink 및 다른 문서의 버전 ID는 편집·복원할 수 없다.
- 웹 본문 저장·복원 및 제목/그룹 변경을 보관한다. 외부 에이전트가 직접 파일을 수정한 중간 버전을 모두 자동 보관하는 감시 시스템은 아니다. 다음 웹 저장 직전의 현재 파일은 보관된다.
- 버전 이력은 같은 PVC에 있으므로 외부 백업을 대체하지 않는다. 백업/복구 대상에는 문서와 `/data/.document-history`를 함께 포함해야 한다.

## 배포·되돌리기

기존 배포 이미지와 Deployment 설정을 서버 내 작업 디렉터리에 백업한다. 새 이미지를 사설 레지스트리에 push하고 digest로 고정한 뒤 기존 Deployment의 app/initContainer 이미지만 갱신한다. 계정·Secret·PVC는 유지한다. Recreate 전략 때문에 배포 중 짧은 접속 중단이 있을 수 있다.

되돌리기는 백업한 이전 digest로 app/initContainer 이미지를 되돌린다. 버전 이력은 기존 이미지에서 읽지 않지만 PVC에 남는다. `.document-history`를 직접 삭제하지 않는다.
